# WP-1 — Storage: FS default, S3 optional, one streaming route

**Date:** 2026-07-02 · **Package:** WP-1 of `GOAL.md` · **Proves:** Final State F1
**Status:** implementing

## Problem

Asset bytes (uploaded sources, normalized markdown, rendered artifacts) live in MinIO, and the
browser reads raw source bytes via **presigned URLs** minted against a second, browser-reachable
MinIO endpoint (`MINIO_PUBLIC_ENDPOINT`). That means: (a) a mandatory MinIO container + init
one-shot in the default stack, (b) asset reads that bypass the API's principal boundary entirely
(anyone with the URL reads the object for the TTL), (c) dual-endpoint presign plumbing that only
exists to work around compose hostnames, and (d) two call sites (`render_service`,
`builder/workflow`) reaching into the store's private `_client`/`_bucket`.

## Design

### 1. Backend protocol

`aleph_rks.asset_store` becomes a `typing.Protocol` plus two implementations and a factory:

```python
class AssetStore(Protocol):
    def put_source_asset(*, project_id, source_id, data, mime_type, extension) -> StoredAsset: ...
    def put_normalized_markdown(*, project_id, source_id, version_no, markdown) -> str: ...
    def put_bytes(*, key: str, data: bytes, mime_type: str) -> StoredAsset: ...
    def get(storage_uri: str, *, expected_sha256: str | None = None) -> bytes: ...
    def stream(storage_uri: str, *, chunk_size: int = 1 MiB) -> Iterator[bytes]: ...
```

- `put_bytes` is the generic write used by the render/builder paths — the private-attribute
  reach-ins are deleted.
- `get` keeps SHA-256 verification semantics (mismatch raises `AssetStoreError`, never silent).
- `stream` is new: chunked reads for the streaming route (no hash check — the route sends
  `ETag: <sha256>` from the DB row instead; full-read verification stays on `get`).

**`FsAssetStore(root: Path)`** — the default backend.
- URIs: `fs://<key>` (key = the same logical layout, below). Bytes at `<root>/<key>`.
- Writes are atomic: write to `<root>/.tmp/<uuid>`, `os.replace` into place; parents created.
- Reads resolve the key against `root` and **reject any path that escapes it**
  (`resolved.is_relative_to(root)`) — `storage_uri` comes from the DB, defense in depth.
- Reading an `s3://` URI raises `AssetStoreError` (and vice versa): backends never silently
  cross. Switching backends does not migrate rows; existing `s3://` rows need the `s3` profile
  or a re-ingest. Local dev data is disposable; that is acceptable and stated here explicitly.

**`S3AssetStore(endpoint, access_key, secret_key, bucket, secure)`** — kept for real S3/MinIO
deployments. Same MinIO SDK client for I/O, **no presign client, no public endpoint, no
`presigned_get_url`**. Bucket ensured at construction.

**`create_asset_store(...)`** — factory selecting by `ALEPH_ASSET_BACKEND` (`fs` default, `s3`
opt-in). Missing s3 config with `backend=s3` raises at startup — fail fast, no silent
`asset_store = None` fallback. The lifespan/worker `None` branches and the routes'
`"asset store is not configured"` checks are deleted: the store always exists.

### 2. Key layout (unchanged)

```
projects/{project_id}/sources/{source_id}/{sha256}.{ext}     ← raw source bytes
projects/{project_id}/normalized/{source_id}/{version_no}.md ← normalized markdown
projects/{project_id}/renders/{source_id}/{sha12}.{ext}      ← rendered assets
projects/{project_id}/artifacts/{artifact_id}/{version}/...  ← builder outputs (as today)
```

`fs://` URIs carry the key verbatim; `s3://<bucket>/<key>` as today. `storage_uri` columns are
untouched (schema change: none; no migration).

### 3. The streaming route

One authenticated route serves **all** asset bytes to the browser:

```
GET /v1/projects/{project_id}/assets/{asset_kind}/{asset_id}
    asset_kind ∈ {source, rendered, artifact-version}
```

- `source` → `Source` (by id, scoped to project) → current `SourceVersion` → `SourceAsset` →
  streams the raw bytes with the stored `mime_type`.
- `rendered` → `RenderedAsset` row by id.
- `artifact-version` → `ArtifactVersion` row by id.
- Response: `StreamingResponse` over `AssetStore.stream`, headers `Content-Type` (from row),
  `Content-Disposition: inline; filename="..."`, `ETag: "<sha256>"`, `Cache-Control: private,
  max-age=3600` + `If-None-Match` → 304. Unknown id / cross-project id → 404.

**Auth posture.** The route sits inside the normal principal boundary: `AuthMiddleware` resolves
the principal (401 without a bearer in `oidc` mode — unit-tested), project scoping via
`ProjectScopeDep` (membership required, 404 on foreign projects), read allowed at VIEWER like
every other project GET. Known, accepted gap (GOAL §out-of-scope): in `oidc` mode an `<iframe>`
cannot attach a bearer header — same class as the documented SSE×OIDC gap; local mode (the only
deployed mode) is unaffected.

**Ledger posture.** No ledger event: rule 4 covers **mutations**; no existing GET writes ledger
events and asset reads are no different. Reads remain observable via request logs/OTEL.

### 4. Consumers

- `routes/sources.py`: the presign route (`GET .../sources/{id}/asset` → `AssetURLOut`) is
  **deleted**, replaced by the streaming route. `/normalized` unchanged (server-side `get`).
- `apps/web` `SourceViewer`: the raw tab's iframe points **directly** at the streaming route URL
  (no JSON URL-hop, one less self-fetch); the normalized tab is unchanged. (Full A2UI rebuild of
  this surface is WP-4.)
- `render_service.record_render` and `builder/workflow._put_artifact_bytes` switch to
  `put_bytes`.
- `audit/checks/library-source-viewer.sh` retargets to the streaming route (expects 200 +
  matching content-type instead of a presigned URL).

### 5. Compose / bootstrap / env

- `minio` + `minio-init` move to `profiles: ["s3"]` — a fresh `bootstrap-local.sh` boots **no
  MinIO container**; `docker compose --profile s3 up` restores it for s3-backend testing.
- `aleph-api` + `aleph-workers`: drop `MINIO_*` env + minio `depends_on`; gain
  `ALEPH_ASSET_BACKEND: fs`, `ALEPH_ASSET_ROOT: /data/assets`, and a shared **bind mount**
  `../../data/assets:/data/assets` (api writes, workers read; host-run integration tests see the
  same files). `/data/` is gitignored.
- Settings (api + workers): `aleph_asset_backend` (`"fs"` default), `aleph_asset_root`
  (default `data/assets`), `aleph_s3_endpoint/access_key/secret_key/bucket/secure` (None/False
  defaults, required iff backend=s3). **Removed keys:** `minio_endpoint`,
  `minio_public_endpoint`, `minio_root_user`, `minio_root_password`.
- `.env.example`: MinIO block replaced by an asset-storage block; `MINIO_ROOT_USER/PASSWORD` +
  `ALEPH_S3_BUCKET` stay only inside a clearly-marked *opt-in s3 profile* section (they
  configure the minio container itself when the profile is enabled).
- `bootstrap-local.sh`: minio bucket comment + console-endpoint line removed.
- `tests/e2e/conftest.py`: MinIO env defaults removed; `ALEPH_ASSET_ROOT` defaults to the
  repo-level `data/assets`.

### 6. Deletion list

- `AssetStore.presigned_get_url`, the second presign `Minio` client, and the
  `public_endpoint` constructor arg.
- `MINIO_PUBLIC_ENDPOINT` everywhere (settings, compose, `.env.example`).
- `GET /v1/projects/{pid}/sources/{sid}/asset` (presigned-URL JSON route) + `AssetURLOut` +
  the frontend `useQuery` hop that consumed it.
- The `asset_store is None` fallbacks (lifespan, sources routes, aiq_internal) — the store is
  now always constructed or startup fails.
- MinIO from the default compose stack (`minio`, `minio-init` → opt-in `s3` profile).
- `minio_*` settings keys from api + workers settings.

### 7. Security posture

- Asset bytes never leave the principal boundary: no presigned URLs, no direct-to-store browser
  traffic, no anonymous read window. Project scoping enforced per request at read time (a
  revoked member loses access immediately — presigned URLs couldn't do that).
- fs backend: path-traversal guard on every read; writes only under `ALEPH_ASSET_ROOT`; atomic
  replace prevents torn reads by the workers.
- Streaming responses carry `X-Content-Type-Options: nosniff`, and both filename parts in
  `Content-Disposition` are sanitized (the extension is uploader-influenced).
- **(Amended during review, 2026-07-03.)** The original residual-risk note here claimed an
  uploaded HTML/SVG source running as active content on the API origin was harmless because
  "the API origin carries no cookies/tokens". Adversarial review falsified that rationale: in
  `local` auth mode every same-origin request carries ambient auth, so API-origin script has
  full API reach. Rather than accept a mischaracterized risk until WP-4, the route now sends
  `Content-Security-Policy: sandbox` on every non-PDF response — iframe-sandbox semantics
  enforced server-side, covering direct URL opens too. PDFs are exempt (Chromium's PDF viewer
  refuses to render sandboxed documents — verified empirically; it is not page-context script).
- s3 backend: credentials live in service env only (as before); nothing browser-facing.
- Agent paths are unchanged: agents still reach assets only through typed service methods
  (rule 3); workers keep using the store directly as a service, never the route.
