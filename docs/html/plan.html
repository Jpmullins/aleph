Stop. The instrument is lying. Part 0

scripts/acceptance.sh is the artifact that answers “is Aleph finished”. Before any of the work below begins, one week making it honest — this is the single biggest risk in the plan.

$ ./scripts/acceptance.sh --quick
pass=23  fail=0  red=0  skip=18 (not built)
INCOMPLETE — 18 part(s) not built. Nothing regressed.
$ echo $?
0

It runs 23 of 41 rows, exits 0 on eighteen skips, and is never invoked by CI — grep -c acceptance.sh .github/workflows/ci.yml returns 0.

It certifies things that are false.

Acceptance Part D — the entire product thesis — is six ✅ rows resolved against packages/aleph-kernel/tests/, a module with no callers outside its own tests. D6 asserts a ported skill “loads and works”; that skill lives at repo-root skills/literature-review/ while the agent’s skills root is apps/api/src/aleph_api/skills/. The running agent cannot see the skill its green check certifies.

So the failure mode is not “a cluster runs late”. It is: five clusters land plausible work over three months, each green against its own criteria, and the first honest end-to-end measurement happens at the end — against an instrument that was already lying before anyone started.

What is actually broken right now Part 2

Verified live, not remembered. These reorder everything.

Retrieval is dead on the deployed instance.

0 chunks · 75 sources · 843 wiki pages

Model profiles bind the embedder to titan-embed-v2; the gateway serves titan-embed-text-v2. Wrong by one word. And because chunks are written only after the embed returns, one bad model name also killed the lexical leg — which needs no model at all. The belief layer has never run.

CLAUDE.md states that claim→chunk grounding is “populated on the real write path instead of only in fixtures”. On live data that is 0 of 786.

access_scope is a write-only column, schema-wide. 70 assignment sites, zero query filters. Every migration adds it. CLAUDE.md lists it as a review-held rule; it is in fact the largest single instance of the defect class CLAUDE.md itself calls dominant — and it is nobody’s. Enforce it or delete it.

The frontend has no test runner — no Vitest, no Playwright — and three clusters wrote criteria against one. pnpm-workspace.yaml declares a member directory that does not exist.

And the UI has no error containment or keyboard access. Across 60 files: 49 aria attributes, 1 onKeyDown, 0 .focus() calls, 0 error boundaries. One thrown render error blanks the workspace. The Board is a spatial canvas with no keyboard access whatsoever.

What the reviewers rejected Part 4

All six returned needs-work. None approved. They found 74 criteria that could not fail or could not be run, 68 false claims about the codebase, 77 missing pieces of work and 43 sequencing problems. Three worth reading, because each is a way a plan can look rigorous and measure nothing:

1

A criterion that passes today

Cannot fail

“Writing over a bundled skill is refused” was marked fails today. The reviewer reproduced it: deepagents’ write already has a file-exists guard, so the check would go green on day one without the fix. It is reproducible through edit — which rewrote a skill’s instruction from “Always cite sources” to “Never cite sources”. Split into two criteria against the two real vectors.

2

A gate on a role that does not exist

Decorative

“Authoring a plugin requires more than project scope” — there is no operator role. ProjectRole is OWNER/EDITOR/VIEWER and every candidate is a project role, so a user who owns their own project clears the gate and gets code execution inside the shared API process. The replacement tests both halves, including an instance-level authority a project owner cannot satisfy.

3

A pane that goes green without painting

Producer, no consumer

“The plugins pane is reachable” passes the instant the registry gains an entry — while _build_tab_messages is a hardcoded if-chain ending in raise NotFound, so the pane renders nothing. Exactly the producer-with-no-consumer defect CLAUDE.md names as dominant. Replaced with a test that opens the stream and asserts components arrive.

Horizon Part 5

Five independent scans, deliberately different lenses, each required to name the number that would move. 63 opportunities: 45 adopt, 10 trial, 3 assess, 5 hold. The ones that change this plan:

  • Prompt caching is silently a no-op on the agent path — ~10k tokens of identical prefix re-sent every turn. Two to three days, and the likely cause of the gateway rate limiting.
  • The SpawnLedger is written and enforces nothing. Depth, fan-out and budget brakes exist in the kernel and no code path consults them.
  • The agent compacts against a guessed context window rather than the one the gateway reports.
  • The Grounding surface is complete on five layers and unreachable — one handler branch away from working.
  • 716 lines of dead frontend to delete, plus a sweep so it cannot come back.
  • Rebind the embedder to cohere-embed-v4 at 1024 Matryoshka dimensions — one day, and it is on the critical path.

Two findings argue this plan is wrong. Both deserve a decision before work starts.

Do not build the plugin system. The boot manifest may already be one, and the honest move is to prove that with a failing test rather than write a second abstraction beside it. A genuine fork in the road — decide it in docs/decisions.md, do not discover it two weeks in.

Agent-authored code must run in code-runner — cap-dropped, read-only rootfs, network-partitioned — and never through exec() in the FastAPI process, which is what the kernel’s current skill loader does. This one is not optional. It is a security boundary and the plan adopts it.

Review and iteration are steps, not attitudes. Review prefers mutation testing — break the thing, confirm the check goes red, restore. A check never observed failing proves nothing, which is exactly how Part D came to certify a module the product does not load. Iterate names what a second pass improves, so the gap between “shipped” and “good” is scheduled rather than hoped for. And the horizon scan re-runs at each of the eight numbers, because the state of the art moves faster than this plan will be executed.

Explicitly not doing Part 7

Each belongs in docs/decisions.md as a dated entry, so it stops being re-litigated every planning round.

  • The kernel stays in Python. Close D5 — 57 workstreams already assume it.
  • The wiki is not deleted this cycle. One workstream produces the deciding measurement; nothing schedules the deletion.
  • OIDC is not shipped. Everything is measured in local mode.
  • access_scope is deleted, not implemented. Route-side role checks at ~20 sites are the real control; a second unread authorization concept in every table is worse than none.
  • audit/ is deleted. Three overlapping registries of intent already disagree in both directions. One gate.
  • aleph-datasets is deleted. Its only importers are the migration runner and a consistency test.
  • No async subagents, no MCP client, no Enterprise Intelligence this cycle.
  • No multi-tenancy, collaboration, presence or mobile layout. One user, three projects.
  • No new workspace package. The count holds at ≤21 and should ratchet down.
