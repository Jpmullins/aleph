# WP-6 — Wiki trust layer

**Date:** 2026-07-04 · **Package:** WP-6 of `GOAL.md` · **Proves:** Final State F4
**Status:** implementing

## Problem

A compiled wiki page has no notion of how fresh or trustworthy it is. There is no freshness
score, no staleness refresh, no way to retract a source and see what it poisons, and briefs
give no signal when the pages they were built from have since changed. WP-6 adds the trust
layer: freshness scoring, a refresh job with approval gates, source retraction with
blast-radius, and drift badges — all keyed to the existing ledger + surface-delta substrate.

## Design

### 1. Schema (one migration, `down_revision = wp4_card_spotlight`)

- `wiki_pages`: add `volatility` (String(8), default `"warm"` — `hot`|`warm`|`cold`),
  `verified_at` (timestamptz, nullable), `freshness` (SmallInteger, nullable — 0–100).
- `sources`: add `retracted_at` (timestamptz, nullable) + `retraction_reason` (Text, nullable);
  `status` gains the value `"retracted"` (free String, no enum alter).
- `wiki_claims`: `confidence`/`status` are free strings already — WP-6 uses a `retracted`
  confidence + `contested` status without a schema change; add nothing.
- Additive, nullable/defaulted; `alembic check` clean.

### 2. Freshness score (curator-computed, deterministic)

`aleph_wiki.freshness.compute_freshness(page, *, revision, citations, source_versions, now)` —
a **pure function** returning an int 0–100 as the sum of four 0–25 dimensions:
- **Recency** (0–25): half-life decay on `verified_at` (fallback `last_compiled_at`), half-life
  by volatility — hot 30d, warm 90d, cold 365d. `25 * 0.5**(age/halflife)`.
- **Citation health** (0–25): fraction of the page's claims that are cited (have a resolvable
  `Citation` → non-retracted `Source`), scaled to 25.
- **Source freshness** (0–25): half-life decay on the *oldest* contributing
  `SourceVersion.fetched_at` (same volatility half-life).
- **Verification** (0–25): 25 if `verified_at` is set and newer than the current revision's
  `created_at` (a human/agent affirmed the page since its last edit), else a partial by claim
  confidence mix; **0 if any contributing source is retracted** (a retracted source forces the
  page unfresh regardless of the other dims).

Wired as a fourth **deterministic** step in `CuratorService.curate()` (`_recompute_freshness`),
in the stage-1 transaction (math, not generation). It writes `WikiPage.freshness` and, when the
curator ran because of an affirmation path, `verified_at`. Pure-function property-tested;
integration-tested via the curator.

### 3. Refresh job (staleness → ApprovalCard)

New arq job `wiki_refresh_job(project_id, page_id, token)` (never auto-recompiles):
- Selects the page's contributing sources; for each, **re-fetches** via the source's connector
  `fetch()` (a new `SourceVersion`), normalizes, and **fact-diffs** the new normalized markdown
  against the stored `NormalizedDocument.markdown_uri` for the prior version.
- Classifies each source `unchanged` | `updated` | `contradicted` | `unreachable` via
  `LiteLLMClient.chat(capability=CLASSIFICATION, purpose="wiki.refresh.factdiff")` (a bounded
  JSON verdict; `unreachable` on fetch failure, no LLM call).
- Emits **one `ApprovalCard`** per page with `target_kind="refresh_result"` summarizing the
  per-source verdicts. Approve/**skip** (unchanged) → bumps `WikiPage.verified_at = now`
  (re-affirmed, freshness rises). **Flag** (updated/contradicted) → downgrades affected
  `WikiClaim.confidence` to `contested` and sets a page banner flag; **never recompiles the
  page** (a human/agent decides via a separate synthesis run). Both actions write an
  `ApprovalDecision` + ledger event, and enqueue a curator freshness recompute.
- Enqueued by a bounded scheduler pass (a `refresh_stale_pages_job` that picks pages whose
  freshness is below a threshold and `verified_at` older than the volatility half-life) — but
  the per-page job is also directly invocable (the integration test + in-browser drive it on a
  fixture-aged page).

### 4. Source retraction + blast-radius (one shared service)

`aleph_reviewer.retraction.retract_source(session, ledger, principal, *, source_id, reason)` —
the
single path all retraction triggers funnel through:
- Sets `Source.status="retracted"`, `retracted_at`, `retraction_reason`; ledger `source.retract`.
- Walks the **blast-radius join** (the reviewer's `_registry_sources` inverted):
  `Source → SourcePage → Citation → WikiClaim`. For every dependent `WikiClaim`: set
  `confidence="retracted"`, `status="contested"` (ledger `wiki_claim.retract_flag` per claim).
  Each affected `WikiPage` is thereby marked (its claims carry the retracted marker; the page
  surfaces a `retracted-source` badge derived from having ≥1 retracted-confidence claim).
- Also emits a `retracted_source` `ReviewFinding` (severity critical) so it lands in Briefs —
  the same finding kind the WP-2 reviewer `doi_verification` node emits. **Scholar-detected
  retractions** (the reviewer pass) call this same `retract_source` service, so manual retract,
  DOI-verification retract, and scholar auto-detect are one code path. Network-unverifiable
  DOIs never trigger it (WP-2 tri-state `ok=None` → no finding, unchanged).
- A queryable `GET`/service `dependent_claims(source_id)` returns the blast-radius set;
  freshness recompute is enqueued for each affected page.
- Route: `POST /v1/projects/{pid}/sources/{sid}/retract` (EDITOR), ledgered.

### 5. Drift (briefs/artifacts)

- At build time, `ArtifactVersion.lineage_jsonb` records `source_pages: [{page_id,
  revision_id, revision_created_at}]` + the existing `created_at` (generated-at).
- `drifted` is **computed**: an artifact/brief is `drifted` iff any recorded upstream page's
  *current* `current_revision_id` differs from the recorded `revision_id` (i.e. a newer
  revision exists since the brief was built). Exposed as a `drifted: bool` prop on `ArtifactCard`
  (and pinned brief cards) via the surface builder — no stored flag (always live-computed, so
  it can't go stale itself).

### 6. Rendering (WP-4 catalog, delta substrate)

- **Freshness:** `_wiki_messages` populates `page_meta.freshness` + `volatility` +
  `verified_at` on the open page AND `freshness` on each page-list row (F4: badge + sort). The
  `page_meta` prop is `additionalProperties: true`, so no schema change for those; the
  page-list rows get a `freshness` field.
- **Retracted marker:** `ClaimCard.confidence` enum gains `"retracted"`; `WikiPageCard`/
  `SourceCard` get a `retracted: bool` prop (schema bump + renderer — the F3 sweep requires
  producer+renderer together). The reader shows a "⚠ retracted source" banner when any claim
  is retracted.
- **Drift:** `ArtifactCard` gets a `drifted: bool` prop (schema + renderer) → an amber "drifted"
  pill.
- **ApprovalCard:** `target_kind` enum gains `"refresh_result"`; `_approve`/`_reject` in
  `a2ui_handlers.py` get the new branch (skip→verified_at bump; flag→confidence downgrade).
- All trust mutations already append ledger events → the existing `action_ledger_events` NOTIFY
  trigger wakes the surface stream, which re-derives + diffs (no new trigger). No polling.

### 7. Security / rules

- Every trust **mutation** (retract, refresh-approve/flag, claim-flag) writes an
  ActionLedgerEvent in the same transaction (rule 4). *(Amended 2026-07-04:)* freshness-recompute
  is a **derived deterministic score**, not a mutation of authored state — it is written within
  the already-ledgered curate transaction and does not emit its own ledger event (there is no
  content change to attribute). Fact-diff LLM calls go through `LiteLLMClient` with a `purpose`
  (rule 5). Retraction is EDITOR-gated. No auto-recompile
  (F4 explicit). Markdown stays the only write-format.

## What it deletes

Nothing new; it wires the `infobox_jsonb` producer gap noted in WP-4/WP-5 only if trivial
(out of scope otherwise — freshness is the WP-6 curator addition).
