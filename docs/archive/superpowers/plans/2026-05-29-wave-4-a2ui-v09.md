# Wave 4 — A2UI v0_9 shared catalog + delta updates — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the homegrown right-panel A2UI renderer with the upstream `@a2ui` v0_9 stack (`MessageProcessor` + `A2uiSurface` + Generic Binder), define the 17 Aleph cards ONCE in a shared v0_9 `Catalog` used by both the right panel and the Live chat, and have the backend emit real v0_9 messages with incremental deltas.

**Architecture:** Frontend renders via `@a2ui/react/v0_9` (`A2uiSurface`, `createComponentImplementation`, `basicCatalog`) + `@a2ui/web_core/v0_9` (`Catalog`, `MessageProcessor`, `CommonSchemas`, generic binder). Backend (`aleph_a2ui`) emits v0_9 `ServerToClientMessage`s — full surface on connect over a new SSE endpoint, then diff-based `updateDataModel`/`updateComponents` deltas. Card actions keep posting to the existing `ActionRouter` (`/cards/actions`). The 17 cards are defined once and consumed by both the panel and the CopilotKit chat renderer.

**Tech Stack:** React 19 + Vite, `@a2ui/react@0.10` + `@a2ui/web_core@0.10` (v0_9 subpaths), `@copilotkit/a2ui-renderer`, zod (v3-style `CommonSchemas` resolving against app zod 4.4.3 — see Task 1), FastAPI SSE, `aleph_a2ui` Python.

**Build order:** Task 1 (spike — de-risk the pattern + zod) gates everything. Then 2 (backend full messages) → 3 (migrate all cards) → 4 (chat shares catalog) → 5 (action routing) → 6 (delta streamer) → 7 (retire homegrown + verification). Each task is one commit. Frontend changes need `docker compose up -d --build aleph-web`; api changes need `up -d --build aleph-api` (baked images, no bind mount).
